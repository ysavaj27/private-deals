Subject: Wealth Manager API – dashboard / pending tasks / send documents / MIS counts not staying in sync

Hi team,

We audited the Private Deals Wealth Manager mobile/web client against the live API contracts. Several screens show wrong or stale counts/lists. Please verify the following from the backend side and align response contracts + aggregation logic.

Base URL pattern: https://www.privatedeals.in/api/
Auth: existing WM business token (same as app).
Success envelope the app expects:
{ "status": 1, "message": "...", "data": <object|array> }

------------------------------------------------------------
1) DASHBOARD vs PENDING TASKS – COUNT MISMATCH (HIGH)
------------------------------------------------------------

The Dashboard and Pending Tasks screens use TWO different APIs for the same UI concepts (KYC / document sign / fund transfer). Users report numbers that do not match across screens and do not update after actions.

A) GET v1/business/dashboard
   (also: GET v1/business/dashboard-pre-ipo)

   App reads from `data`:
   - total_startups (int)
   - total_investors (int)
   - total_amount_invested (number)
   - average_ticket_size (number)
   - pending_kyc (int)                    → shown as "KYC" count
   - pending_document_sign (int)          → shown as "Documents" count
   - pending_payment (number)             → shown as "Fund transfer" count via toInt()
   - top_investors[], sectors[], investment_growth[]
   - investments.monthly[] / investments.quarterly[]
   - investor_chart.kyc[] / investor_chart.active[]

   Hero "Pending" total on UI =
     pending_kyc + pending_document_sign + int(pending_payment)

B) GET v1/business/pending-tasks

   App reads from `data`:
   - pending_kyc (int)
   - document_sign (int)                  ← DIFFERENT KEY than dashboard
   - pending_payment (int)                ← typed as COUNT here
   - pending_aif (int)

Please confirm and fix:
1. Dashboard `pending_*` counts and `/pending-tasks` counts MUST use the same business definition for the logged-in WM (same scope: primary vs pre-ipo if applicable).
2. Align field names OR document the canonical contract:
   - document sign: `pending_document_sign` (dashboard) vs `document_sign` (pending-tasks)
3. Clarify `pending_payment` semantics on dashboard:
   - Is it a COUNT of pending fund-transfer tasks, or an AMOUNT (rupees)?
   - Pending-tasks treats it as int count; dashboard model treats it as double then casts to int for UI. If it is an amount, dashboard Fund Transfer count will be wrong.
4. After KYC completion / document send / fund-transfer status change, both endpoints must return updated counts on the next GET (no stale cache / denormalized counters lagging).
5. Please share sample JSON for both endpoints for one test WM account where:
   - pending KYC > 0
   - document sign > 0
   - fund transfer > 0
   and confirm dashboard counts == pending-tasks counts for the same bucket.

List endpoints used to render Pending Tasks tabs (counts must match list lengths for same filters):
- KYC list: GET v2/business/investor?is_kyc=No&is_active=All&is_aif=All
- Document sign list: GET v1/business/primary-transactions?pending_doc_sign=true
- Fund transfer list: GET v1/business/primary-transactions?pending_payment=true

Please confirm filter semantics:
- is_kyc / is_aif / is_active accepted values: "All" | "Yes" | "No"
- pending_doc_sign / pending_payment: boolean query flags
- Count on /pending-tasks for each bucket MUST equal the number of rows returned by the matching list filter for that WM.

  "startup_name": string,
  "logo": string|url,
  "approved_mis": [
    {
      "id": int,
      "title": string,
      "document": string|url,
      "description": string,
      "created_at": datetime
    }

UI count per startup = length of `approved_mis` only.

Please confirm:
1. Response is always startup-grouped with `approved_mis` (not a flat list / not key `mis` / `pending_mis`).

3. If pending/unapproved MIS exists, under which key? (App currently ignores anything except `approved_mis`.)
4. Share one real sample payload with at least one startup that has MIS files.
